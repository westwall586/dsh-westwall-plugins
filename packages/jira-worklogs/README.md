# Jira 工时记录 使用手册

> **状态：草稿。** 接口与配置仍可能变。未发布 npm，推荐从本地目录安装，或用固定提交从 GitHub 安装。

在 DSH 的侧栏面板里查看当月工时缺口，就地起草，确认后写入 Jira。

## 快速开始

### 安装

本地目录安装适合开发和试用。

```sh
dsh plugin --profile <profile> add link:/绝对路径/packages/jira-worklogs
```

固定提交安装适合分享和换机。

```sh
dsh plugin --profile <profile> add \
  "git+https://github.com/westwall586/dsh-westwall-plugins.git#<commit>&path:/packages/jira-worklogs"
```

`<commit>` 是 40 位提交 SHA。两种方式都直接加载仓库里入库的 `lib/`，安装时不需要构建。

本地 `link:` 安装后如果改了 `src/`，先在包目录跑 `pnpm build` 再重启，改动才会生效。

安装完成后重启 DSH。首次加载会启用侧栏入口和插件页配置表单。

### 配置

在侧栏进入「插件」页，打开「Jira 工时记录」详情页，填写「Jira 连接」，点「保存」。

至少需要填写「地址」「账号」「密码」。自签证书环境按需打开「高级」里的「校验 SSL 证书」。

Git 素材可选。不配置也能生成草稿，只是草稿里没有提交记录可以参考。完整配置项见下面的「配置」一节。

### 首次打开

点侧栏「Jira 日志」。配置正确时，首屏应包含以下内容。

- 顶部标题「Jira 日志」与说明。
- 当月标题，例如「2026 年 11 月」，右侧显示「缺口 N 天」。
- 月历。今天带「今」，有缺口的工作日带「缺」，已填满的工作日带「✓」。
- 今天默认选中，下方显示当日已填工时与缺口。
- 当天有 Git 提交时，显示「N 次推送 · M 个提交 · 项目名」。
- 底部显示「手动素材」区域与「▸ 查同事日志」。
- 页脚有「刷新」。当天仍有缺口时还显示「生成日志」。

配置缺失时，面板显示「缺少连接配置」，按提示回到插件页补齐即可。

## 配置

### Jira 连接

| 项 | 说明 |
|---|---|
| 「地址」 | Jira 服务器根地址，例如 `https://jira.example.com`。末尾斜杠会被去掉。 |
| 「账号」 | Jira 用户名。 |
| 「密码」 | Jira 密码或 API token。保存后不再回显。 |
| 「校验 SSL 证书」 | 默认关闭，适合自签证书。公开证书环境建议打开。 |

Jira 连接需要能读取当前用户与工时。Jira 7.2 及以上版本的工时 JQL 才能正常工作。

### Git 实例

| 项 | 说明 |
|---|---|
| 「实例名」 | 实例的显示名，同一 profile 内唯一。 |
| 「地址」 | GitLab 实例根地址，例如 `https://gitlab.example.com`。不要带 `/api/v4`。 |
| 「token」 | 能读取 GitLab API 的 Personal Access Token。 |
| 「SSL」 | 是否校验该实例的证书。 |

每个实例的地址与 token 必须同时非空才会生效。可以添加多个实例，分别填地址与 token。只配置地址或只配置 token 的实例会被忽略。

Git 实例当前走 GitLab REST API，读取推送事件与提交。自建实例的证书不受信任时关闭该实例的 SSL 校验。点「+ 添加实例」新增一行，点「删除」移除一行。

### 仓库过滤名单

「仓库过滤名单」是排除名单。每行一个子串，仓库路径包含该子串就被排除。默认空名单。

常用做法是排除状态库、镜像仓库、文档仓库等不需要计入工时素材的仓库。

### 环境变量覆盖

调试时可以用进程环境变量覆盖 Jira 连接。环境变量优先级最高。

| 变量 | 作用 |
|---|---|
| `JIRA_SERVER` | 覆盖 Jira 地址。 |
| `JIRA_USERNAME` | 覆盖账号。 |
| `JIRA_PASSWORD` | 覆盖密码或 API token。 |
| `JIRA_VERIFY_SSL` | 设为 `1`、`true`、`yes` 或 `on` 时校验 SSL。 |

环境变量只覆盖 Jira 连接，不覆盖 Git 实例与仓库过滤名单。

### 数据位置

暂存与手动素材保存在 `~/.dsh/storages/dsh_jira_worklogs/`。

插件配置保存在当前 profile 的插件行配置里。移除插件行后，插件不再读取这些配置。

### 运行依赖

运行期第三方依赖只有 `undici` 与 `zod`。`undici` 负责 Jira 与 GitLab 的 HTTP 请求，`zod` 负责存储域 schema。`zod` 固定在 `4.6.6`，与 `dsh-storage-domain` 的精确 pin 对齐。升级平台包时同步检查。

## 日常使用

### 月历与日详情

月历固定显示当月，不提供翻月。未来的日期不可点。周末与未来日期有单独的样式，有缺口的工作日高亮。

点选一天后，日详情显示当天已登记的工时与任务，下面是当天 Git 提交摘要。没有 Git 素材时显示「无提交素材」。

日详情的「已填 Xh / 缺口 Xh」按 8 小时工作日计算。当天不是工作日时不显示缺口。

### 就地生成

只有仍有缺口的工作日会出现「生成日志」。点它以后，插件收集当天已登记工时、近几日缺口、Git 提交与「手动素材」，调用宿主默认模型生成草稿。生成在当前面板内完成，不新开会话。

生成期间页面显示「生成中……请稍候」。生成完成后出现草稿表单，每个条目包含任务、开始时刻、结束时刻与工作说明。工时由开始与结束自动计算。

默认模型路由不可用时，面板提示「生成不可用」。到平台设置里检查默认模型后再点「重试」。

### 编辑

草稿里的每个条目都可以改任务、改开始与结束时刻、改说明，也可以删除。需要补条目时点「＋ 从候选任务增补条目」。

开始与结束必须是 `HH:MM`，结束晚于开始。说明不能为空。标红的条目不能提交。

说明以「待用户确认」开头时，输入框会标黄。提交前改写为真实工作内容。

### 提交

点「提交」即显式确认。插件在提交前重新查询当天已填工时，按最新已填值计算缺口。

写入前按任务做五维查重。同一个人、同一天、同一任务、同样时长与同样说明的工时视为已存在，条目标记为「○ 已跳过」，不会重复写入。

写入后回读该任务的工时列表。回读命中时标记「✓ 已写入」。回读没有命中时标记「⚠ 不确定（需人工核对）」，并给出「→ 到 Jira 核对」链接。

提交被拒时显示「提交被拒」与具体原因。常见原因是当天总工时不足 8 小时，或说明仍是待确认草稿。

### 结果不确定

「不确定」表示请求已经发出，但回读没有确认是否落库。插件不会自动重试。

看到「⚠ 不确定（需人工核对）」时，先点「→ 到 Jira 核对」。已经写入就删除该条，没有写入再重新提交。

如果编辑过不确定条目再提交，插件会弹出确认，提醒先到 Jira 核对，避免写重。

### 暂存与重试

写入失败或结果不确定的条目会按日暂存。面板顶部出现提示条，显示「X 条待重试提交」或「N 日共 M 条待重试提交」。

点「查看」展开逐日清单。点「打开」把该日暂存回显到草稿表单。点「放弃」删除该日暂存，不会写入任何 Jira 内容。

草稿表单里出现「再次提交（未成功项）」时，它只重提上次失败或不确定的条目，已经写入的条目不会重复提交。

暂存依赖 DSH 存储。存储不可用时，提示条显示「存储不可用，暂存功能暂不可用；月历与日详情不受影响」。这时失败内容无法暂存，请保持面板打开并在表单内处理失败条目。

### 手动素材

「手动素材」用来补充编码外的工作，例如会议、评审、沟通。选择任务，填写做了什么，生成时会作为该任务的素材。

素材在停止输入约 800 毫秒后自动保存。保存失败时显示「保存失败」与「重试」，已输入的内容不会丢。清空文本并保存等于删除该条。

没有缺口的日子不显示填写引导。存储不可用时，素材区显示降级提示，月历与日详情不受影响。

### 查同事日志

页面底部有「▸ 查同事日志」，默认收起。展开后输入同事中文名或登录 ID，可选起止日期，点「查询」。

查询只读，不会写入任何内容。结束日期会自动卡到今天。名字匹配到多个账号时，结果会列出候选并要求改用登录 ID。

查询窗口没有日志且日期范围有限时，插件会回查该同事最后活跃的自然周，并在结果上方说明回溯范围。该同事没有任何可见日志时，结果显示「无任何可见日志」。结果只包含当前账号可浏览项目内的工时。

查询与自己的生成、提交流程互不锁定。收起查询区不会取消已经发出的请求。

## 故障排查

| 现象 | 先查 |
|---|---|
| 面板显示「缺少连接配置」 | 到「插件」页的「Jira 工时记录」详情页填写「地址」「账号」「密码」并「保存」，回到面板点「刷新」。 |
| 面板正文是「Jira 认证失败（401/403）」 | 账号或密码无效。使用 API token 时确认账号与 token 匹配。部分 Jira 网关对无效凭据返回 200 空响应，插件会把空的当前用户视为凭据无效。 |
| 日详情显示「无提交素材」 | 检查「Git 实例」的地址与 token 是否成对填写，SSL 是否适合该实例，「仓库过滤名单」是否把目标仓库排除了。只有当天产生过推送的仓库才会出现提交。 |
| 点「提交」后没有写入 | 看每条的结果。「○ 已跳过」是查重命中。「⚠ 失败」是 HTTP 失败，检查权限与字段。「⚠ 不确定」先到 Jira 核对，不要直接重提。「提交被拒」按提示修正后重试。 |
| 提示「提交失败」 | 请求本身抛错，常见原因是草稿已过期、网络中断或登录状态失效。刷新面板后重新生成再提交。 |
| 安装后侧栏没有「Jira 日志」 | 重启 DSH。确认插件装在当前 profile 并已启用。不要同时安装根聚合包和子包，否则启动会报 `duplicate loader entry id`。确认 DSH 版本满足包里的 `engines.dsh` 与 `peerDependencies`。 |
| 生成失败或提示「生成不可用」 | 到平台设置确认默认模型可用。生成只使用宿主默认模型，不读取插件自己的模型配置。 |
| 提示「存储不可用」 | DSH 存储域不可用。月历与日详情仍可用，暂存与素材降级。重启 DSH 后观察是否恢复。 |

## 卸载与清理

在「插件」页移除，或用命令行。

```sh
dsh plugin --profile <profile> remove @westwall/dsh-jira-worklogs
```

包名以 `package.json` 的 `name` 为准。

暂存与手动素材默认保留在 `~/.dsh/storages/dsh_jira_worklogs/`。不再需要时手动删除该目录。删除前确认没有要留存的草稿。

卸载后建议撤销用过的 Jira API token 与 GitLab token，尤其是曾经填进配置或环境变量的 token。

插件配置保存在当前 profile 的插件行。移除插件行后，插件不再读取这些配置。要确认是否有残留，检查当前 profile 的插件配置。
