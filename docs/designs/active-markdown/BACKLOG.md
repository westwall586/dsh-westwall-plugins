## 1. 批注归档（独立功能）

**定位**：用户做过的每一条批注都留在一个单独的归档区，不管 Agent 有没有对应处理，
用户都能核查这份文档的演进路径。它**独立于易失 store**（
[STATE-STORE-TECH.md](STATE-STORE-TECH.md)），有自己的持久化。

**本轮不做**。在它落地前，清批注就是清：文档关闭或外部修改时，批注内存与磁盘
记录一并清除。归档功能完成后，这两处“清”改为“清入归档”。

**要定的事**：归档的存放位置与格式；归档与“这一轮反馈已发送”的关系；归档区的
入口（插件页？文档侧栏？对话里？）；是否跨会话可查。
