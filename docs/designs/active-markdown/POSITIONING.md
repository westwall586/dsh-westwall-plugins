# Active Markdown 产品定位

> 状态：草案（2026-11-16）。本文件只定产品方向与边界，不含实现。阶段、验收与风险见 [ROADMAP.md](ROADMAP.md)。

## 1. 一句话

Agent 写的 Markdown，能译、能批、能改，改完只看变化。

读、译、批、改、变，都在右侧栏的同一个页面里完成。

## 2. 问题

在 DSH 里，Agent 产出的长文档（技术方案、调研报告、PRD、变更说明、文章草稿）通常落在工作区 `.md` 文件里。读、批、改、确认四个动作分散在四个地方：

- **读**：原生预览是通用渲染，没有目录，没有 Mermaid/Callout；窄栏与全屏的阅读体验一般。
- **批**：只能在聊天里打字复述，指代不清；或者把原文复制出来再补意见。
- **改**：用户自己的一处小修也要让 Agent 代劳，或者跳出 DSH 用外部编辑器。
- **确认**：Agent 改完，用户要重读全文才能确认改对了没有。

结果是每轮审阅都有三次上下文切换（文档 → 聊天 → 文档），审阅成本随文档长度线性上升。

## 3. 目标用户与场景

- 单个开发者与 Agent 协作，文档是交付物而不是随手笔记。
- 典型文档：技术方案、调研报告、PRD、变更说明、发布说明、长文草稿。
- 典型节奏：Agent 写初稿 → 用户批注 → Agent 修订 → 用户只看变化 → 通过或再批。

不面向：多人协作审阅、文档发布与托管、跨项目文档管理、通用办公格式。

## 4. 产品承诺

1. **读**：接管 `.md` 默认渲染。目录、代码、表格、图片、front matter、Callout、Mermaid、数学公式；窄栏与全屏都可用；跟随 DSH 明暗主题。
2. **译**：原文 / 译文 / 对照三种视图；按块对齐；代码与链接不被破坏；译文缓存；模型未配置时原文仍可读。
3. **批**：选区与整块批注；原文、行号、标题路径、标签（必改 / 建议 / 疑问）；结构化反馈放进输入框，由用户确认后发送。
4. **改**：在同一个页面切到源码编辑；显式保存；文件版本守卫；与 Agent 并发写入时显式冲突，不静默覆盖。
5. **变**：以“上次审阅”为基线，做块级变化标记；只看变化；支持多轮审阅回溯。

## 5. 形态

一个 DSH bundle，两个半体：

- **Host 半体**：文件读写与版本、审阅基线存储、模型调用、可选的 Agent 工具。
- **Client 半体**：接管 `.md` 的渲染页面、目录、批注、翻译、编辑与变化标记。

没有独立 Web 服务，没有 CLI，没有 SQLite，没有项目登记。工作区、会话、文件树都复用宿主。

## 6. 核心动线

1. Agent 把长文写成工作区 `.md`，而不是整篇贴进聊天。
2. 用户从右侧文件列表点开，直接进入 Active Markdown。
3. 读：目录跳转；需要时切译文或对照。
4. 批：选中文字或整块，写批注、打标签；发送到输入框，确认后发出。
5. Agent 修订；文件变化后页面自动刷新，标出“自上次审阅以来”的变化。
6. 用户只看变化处；小的措辞问题直接切编辑模式改掉并保存；继续批或点通过。

## 7. 非目标

- 不是通用 Markdown 编辑器或 IDE：MVP 单文件、源码编辑；不做多文件树、全局搜索替换、编辑器插件体系。
- 不做 WYSIWYG 或块级富文本编辑（列为后续）。
- 不做发布、快照服务、项目登记、文档库。
- 不做独立 Web 服务或 CLI。
- 不做自己的主题系统，只消费 DSH token。
- 不在文档里重造问题卡与计划审批，用原生 `ask_user_question` 与 plan review。
- 不接管 PDF、Office、HTML、图片预览。
- 不做多人协作、评论同步、云端存储。

## 8. 与 DSH 的关系

### 8.1 接入原则：继承容器，替换渲染

DSH 的 Markdown 不是一个独立页面，而是“文档预览 tab”里的一种渲染实现。所以接入方式是：

- **不注册新的文件类型或 tab 类型**：文件地址仍由原生文档预览 tab 认领。
- **只注册一个 renderer implementation**：替换 `.md` 的正文渲染层，`priority: 'extension'`，默认选中；原生 Markdown 仍在下拉里。
- **路径、刷新、外部打开、文件列表、全屏、tab 生命周期全部继承**，不重写。
- **不读宿主 DOM、不 patch 宿主组件、不做 overlay**：只用宿主提供的渲染器注册与 slot。
- **卸载即恢复**：渲染器注册属于 effect，插件停用后 `.md` 立即回到原生 Markdown。

一句话：**基于原生的文档预览容器扩展，替换其中的 Markdown 渲染实现。**

### 8.2 能力归属

| 能力 | 宿主机制 | 用法 |
|---|---|---|
| 文件类型与 tab | 原生文档预览 tab（`text` 类型） | 继承，不注册新类型 |
| 路径、刷新、外部打开 | tab 头部与 `document.actions` 席位 | 继承，不重写 |
| 文件列表导航 | 预览内置的 Session 文件导航 | 继承，不重写 |
| 全屏与会话上下文 | 右侧栏与 tab 生命周期 | 继承 |
| 接管默认渲染 | `ctx.documentPreviews.register` | `extensions: ['md','markdown']`、`priority: 'extension'`；原生渲染器保留下拉 |
| 正文渲染与图片 | `sidebar.right.tab.document` 正文 | 自建 |
| 文件读取与版本 | `ctx.fs` / `remote.workspaceFiles` | 自建读取，版本守卫 |
| 审阅基线 | `ctx.storageDomain` | 只存基线快照、轮次、翻译缓存元数据 |
| 反馈投递 | `inputActions`（优先）/ `session.prompt`（退路） | 结构化反馈插入输入框 |
| 主题 | `--dsw-alias-*` token | 一套排版，跟随明暗 |
| 提问与审批 | 原生 ask / plan review | 不重复实现 |
| 逐轮代码 diff | deliverables changes-review | 保留原生；Active Markdown 补文档级变化 |

> 这些机制来自本机 DSH 0.2.2-rc.3 的包文档与源码；P0 必须逐项实机验证，尤其 `documentPreviews` 的自加载模式、全屏、动作席位、`inputActions` 与 `ctx.fs` 版本守卫。

## 9. 三种写操作的状态模型

### 9.1 真源

- **文件是内容真源**：插件不复制文档、不建平行文档库。
- **会话日志是反馈真源**：批注一旦发送就是普通用户消息，可 fork、可重放、可引用。
- **插件存储是可丢缓存**：审阅基线、轮次、译文缓存；删掉不影响文档与会话。

### 9.2 性质

| 操作 | 改文件 | 依赖 | 失效影响 |
|---|---|---|---|
| 批注 | 否 | 当前内容与块锚点 | 内容变化后锚点可能失效 |
| 翻译 | 否 | 内容 hash 与模型 | 内容变化后译文缓存失效 |
| 编辑 | 是 | 文件版本 | 未发送批注、译文缓存、diff 基线 |

### 9.3 互斥与防呆

| 场景 | 规则 |
|---|---|
| 有未发送批注，进入编辑 | 阻止；三选一：发送 / 暂存草稿后退出 / 丢弃 |
| 编辑中，切译文或对照 | 阻止；先保存或取消编辑 |
| 译文或对照中，进入编辑 | 自动切回原文视图 |
| 编辑保存成功 | 译文缓存失效；历史批注按块重锚；diff 标记“你的修改” |
| 编辑保存时文件已变 | 版本守卫拒绝写入，进入冲突态；不自动合并 |
| Agent 运行中进入编辑 | 提示“Agent 可能正在修改此文件”，二次确认后允许 |
| 文件被外部改动，编辑中且 dirty | 不替换编辑器内容；提示“磁盘已更新”，由用户决定重载或覆盖 |
| 批注原文已被修改 | 条目标“原文已变”，保留意见，不静默删除或挪位 |

### 9.4 保存与冲突

- 载入时记录 `FsVersion`；保存时用 `ctx.fs.editText`（或等价接口）携带版本。
- 版本不一致时只给三个动作：重新加载（保留草稿可复制）、以我的版本覆盖（二次确认）、取消。
- 原子性由 fs 后端负责；插件不写部分内容、不自己拼临时文件。
- 不做自动合并：Markdown 结构自由，自动合并不可靠；宁可让用户显式选择。

### 9.5 编辑范围

- 仅会话文件系统能解析的普通 `.md` / `.markdown`；拒绝符号链接、目录、非 UTF-8。
- 工作区外文件默认只读；是否可写由会话文件系统判定。
- 不写 `.zh.md` 之类派生文件；译文只是视图。

## 10. 与现有插件的边界

- **friendly-expression**：聊天消息里的 Mermaid 与表达提示词归它。Active Markdown 只处理文档面，不注册 `conversation.chat.markdown.fence`，避免争抢同一围栏。
- **dsh-text-translate**：已卸载，不再维护。Markdown 的翻译阅读由 Active Markdown 的 P1 承接；TXT 翻译不再是目标场景。旧插件留下的 `.zh.md` 与设置是否迁移，P1 再定。
- **deliverables**：逐轮代码 diff 继续用原生；Active Markdown 的 diff 是“文档级、以审阅轮次为基线”，两者互补。

## 12. 成功判据

- 路径、刷新、外部打开、文件列表、全屏全部沿用原生；插件没有重写这些入口。
- 3 条批注从选中到发送不超过 2 分钟，全程不需要复制粘贴。
- Agent 修订后，用户只读变化处即可完成确认，不需要重读全文。
- 200 段文档首次打开小于 1 秒，滚动与目录高亮不掉帧。
- 编辑保存成功小于 300ms；并发冲突全部显式提示，零静默覆盖。
- 明暗主题、窄栏、全屏三种形态视觉一致，无硬编码颜色。
- 卸载后除插件存储目录外无残留；README 写清清理方式。
