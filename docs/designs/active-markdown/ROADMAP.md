# Active Markdown Roadmap

> 状态：草案（2026-11-16）。定位与边界见 [POSITIONING.md](POSITIONING.md)。MVP 完成前不发布，但每阶段结束都要留下可演示的真实会话记录。

## 1. 排序原则

- **先地基，再能力**：P0 只验证“能接管、能正确渲染、能读写”，不堆功能。
- **按用户优先级**：翻译 > 批注 + 变化 > 编辑 > 富渲染 > Agent 闭环 > 收口。
- **每阶段独立验收**：上一阶段没验收，不进入下一阶段；允许并行做只读调研，不并行改同一层。
- **风险前置**：接管默认渲染、全屏、版本守卫、输入框插入都在 P0 见结论。
- **量级是相对工作量**（S/M/L），不是工期承诺。

## 2. 阶段总览

| 阶段 | 目标 | 核心验收 | 量级 |
|---|---|---|---|
| P0 | 地基与接管 | 文件列表点开即 Active Markdown，内容正确，全屏可用 | S |
| P1 | 翻译 | 原文 / 译文 / 对照可用，结构不坏，缓存生效 | M |
| P2 | 批注 + 变化 | 3 条批注无复制；Agent 改完只看变化 | L |
| P3 | 编辑 | 源码编辑、显式保存、并发冲突显式 | M |
| P4 | 富渲染与阅读打磨 | 目录、Callout、Mermaid、数学、排版 | M |
| P5 | Agent 闭环 | Agent 主动发起审阅并拿到结构化批注 | M |
| P6 | 收口 | 安装到卸载全流程、文案与数据清理 | M |

依赖关系：P0 的块模型供 P1/P2/P4 共用；P1 的缓存与 P2 的基线共用版本与 hash；P3 的保存依赖 P0 的 `FsVersion`；P5 依赖 P2 定下的反馈格式。

## 3. P0 地基与接管（S）

> 技术取舍、模块划分、验收清单见 [P0-TECH.md](P0-TECH.md)。
> **状态**：Web 版实机验证通过；Desktop 的 Blob 图片、卸载回归待验证。

**目标**：从右侧文件列表打开 `.md`，默认进入 Active Markdown，并正确渲染；为后续能力留好版本、块模型、存储、模型调用的接口。

**交付**

- 注册 document preview 渲染器：`md` / `markdown`，`priority: 'extension'`，默认接管；原生 Markdown 仍可在渲染器下拉中选择。
- Host 半体保留空 `apply()`：P0 不引入自建 RPC、存储或模型调用。
- 打开路径统一：文件树、聊天里的文件链接、交付卡片，都落到同一个渲染器。
- 完整读取（带大小上限，超限回退原生），GFM 渲染：标题、段落、列表、任务列表、引用、表格、代码、链接、图片、front matter。
- 块模型：block id、类型、源行范围、标题路径、纯文本投影；先只供内部使用，不做 UI。
- 主题：只消费 `--dsw-alias-*`；明暗切换不闪、不硬编码颜色。
- 全屏：右侧栏全屏可用；窄栏布局不溢出。
- 文件版本：记录读取返回的 `version`；外部变更由预览自动刷新触发 `reload`。
- 图片：相对与绝对路径统一走字节读取 + Blob URL；失败显示 alt。
- 滚动记忆：沿用父级正文容器，同一 tab 内切换渲染器或重开时恢复阅读位置。
- 错误边界：正文渲染崩溃时显示可恢复状态，不白屏。
- 性能基线：200 段文档首次打开小于 1 秒；滚动无明显卡顿。

**验收**

- 从文件列表点开一份含标题、列表、表格、代码、图片、链接的 Markdown，默认就是 Active Markdown，内容正确。
- 路径、刷新、外部打开、文件列表、全屏都沿用原生，插件没有重写这些入口。
- 全屏、窄栏、明暗主题都正常；原生渲染器仍可切换。
- 文件被外部修改后，页面提示并可刷新。
- 无 console error；无硬编码颜色；渲染器崩溃不白屏。
- 关闭插件后，`.md` 恢复原生预览，不残留接管。

**不做**：翻译、批注、编辑、Mermaid/Callout、目录、diff、Agent 工具。

**P0 必须回答的技术问题**

- `documentPreviews` 的自加载模式（`loading: 'renderer'`）能否稳定拿到全文、重载与取消。
- 全屏呈现与 `sidebar.right.tab.document.actions` 在桌面窗口里是否都可用。
- 图片鉴权路由在 Desktop 的 `dsh-app:` 页面下是否可用；不可用时的字节回退成本。
- `ctx.fs` 的版本读取与 `editText` 版本守卫签名；外部变更 `watch` 在桌面端的可靠性。
- `inputActions` 能否在 session-scope 的 tab 组件里拿到；拿不到时 `session.prompt` 的退路是否满足“先确认再发送”。

## 4. P1 翻译（M）

> 技术方案、提示词、分块与校验规则见 [P1-TECH.md](P1-TECH.md)。
> **状态**：P1 已实现（2026-11-16），P1.1 收口（2026-11-17）。原文 / 译文切换、逐行浮窗、分块、行数与标题序列校验、自动缓存、保存已在 Web 版实机验证；翻译取消、缓存命中保存、过期不可保存与 4 MiB 译文上限已由单测覆盖，待浏览器逐项点选。插件页三项设置经单测与构建验证，未开浏览器点选。延后：token 级流式渲染、分块失败保留已完成块、reasoningEffort 与模型目录。设置按评审决定放在插件页，预览页不放设置。

**目标**：让一份英文 Markdown 在预览页里读到中文，且代码、表格、链接、标题结构在译后仍然可用。译文是视图，不是新文档。

**交付**

- 翻译单元：整份 Markdown。模型返回整份译文，靠“输出行数 = 输入行数”与原文按行号对齐；标题另按「行号 + 层级」序列校验。
- 质量：system prompt 定规则；本地两条校验（总行数、标题块的行号与层级序列）。校验失败降级为“无逐行对照”，不报错。段落与代码围栏内部的结构不校验。
- 视图：原文 / 译文两种。译文里右键任意一行，浮窗显示该行原文；不做全局对照视图。
- 模型：插件页可配 provider / model，缺省跟随会话默认模型；目标语言是三值枚举 `zh` / `zh-Hant` / `en`，默认 `zh`，只有语言名拼进 system prompt。
- 长文：预检 2000 行 / 100000 字符；超限按完整章节切块、顺序翻译，完成后整体校验；超过 16000 行提示不支持。
- 取消：翻译中提供「取消」；`AbortSignal` 经 unary 调用传到 Host，再传给 `llm.stream`，真正中止模型请求。取消后回原文，不写缓存。
- 缓存：源 hash + 目标语言 + 模型 + 提示词版本 + 注释策略 + 补充要求 hash；命中直接显示。按整篇保存，单份译文上限 4 MiB。
- 存储两级：自动缓存进插件存储（不进工作区）；用户「保存译文」写工作区 `.dsh-active-markdown/translate/<code>/`，**镜像源文件相对路径**（避免同名文件撞车），带元数据与根目录的 `.gitignore`。缓存命中可以保存；已保存与过期译文不显示保存入口。
- 设置：放 DSH 插件页（侧栏「插件」→「已安装插件」→「可交互 Markdown」→「翻译设置」），三项是模型、目标语言、代码注释；预览页不放设置。
- 失败：模型调用失败不显示半截译文，原文始终可读；分块中途失败保留已完成块的增量渲染延后。
- 重新翻译：显式入口，可附一句补充要求，覆盖旧结果。
- 入口：工具栏「原文 / 译文」切换；永不自动发起翻译（翻译花钱）。模型未配置时原文零阻塞。
- 旧 `dsh-text-translate` 留下的 `.zh.md` 不读、不迁移，按普通文件对待。

**验收**

- 英文 Markdown 能在原文与译文之间切换；代码、表格、图片、链接结构不变。
- 译文里右键任意一行浮出**该行**原文（单行，不显示整块），点另一行跟随，点空白即关闭。
- 行数与每个标题的层级、行号都一致时浮窗可用；任一不符时浮窗与行号列整体停用，降级为可读译文，明确提示并可重翻。
- 翻译中可取消；取消会中止在途模型调用，回到原文，不写缓存。
- 同一文档二次打开命中缓存，不再请求模型；缓存命中的译文可以保存，已保存与过期译文不显示保存入口。
- 源文件改动后译文标过期，不自动重译、不自动覆盖，保存入口隐藏。
- 取消、失败、未配置模型都有明确状态；原文文件永不被修改。
- 一次翻译只花一次（或块数 N 次）模型调用，解析、校验、配对零 token。

**不做**：编辑、批注、译文编辑、术语库、导出、自动翻译、免费机翻通道、全局对照视图。

## 5. P2 批注（P2a）与变化（P2b）（L）

> 技术方案：批注见 [P2-ANNOTATION-TECH.md](P2-ANNOTATION-TECH.md)（2026-11-17 定稿）。P2a 已实现（2026-11-17），单测覆盖选区锚点、组件帧、草稿持久化、反馈附件、四路发送判定、审阅快照与清理；Web/Desktop 交互仍待实机逐项复核。P2 拆成两段：P2a 先做批注、反馈投递、草稿持久化、发送后清空与旧版快照；P2b 再做块级变化。

**目标**：完成“读 → 批 → 发 → 改 → 看变化”的核心闭环。

**P2a 交付**

- 批注：原文选区（同一行、跨行、跨文本块）；组件整块（表格、代码，后续 Callout / Mermaid 等富组件）；只有意见，不设标签；编辑、删除、撤销。
- 草稿：按 session + 文档持久化；刷新、重启 DSH 不丢；20 份文档 / 30 天，LRU + TTL。
- 锚点：行级文本偏移 + 前后文 + 块 id；组件用块 id + 类型 + 内容签名；精确匹配 → 唯一搜索 → 无法定位，不做静默块级降级。
- 反馈：生成 Markdown 文件，文件名与文件头带 `roundId`；用 `conversation.createDrafts` + `inputActions.addAttachments` 加入输入框；不自动发送。
- 发送判定：session 级 committer 按 `draftAttachmentId` + `roundId` + `fileHash` + 批注草稿存在性判定；两个文档可分别或同时发送，Web Clipper 的附件不参与。
- 清空与旧版：附件进入会话后清空对应文档的批注；发送前的全文快照从 pending 转正到 `.dsh-active-markdown/reviews/`，保留 5 轮 / 30 天 / 50 MiB。
- 译文：不允许批注；选区右键只给「查看原文」与「复制」。
- 组件外壳：`ComponentFrame` 统一标签、动作区与批注状态；全屏、折叠先留槽。
- 基础目录：留到 P2b 或 P4。

**P2b 交付**

- 基线：读取最近一轮全文快照与当前文件。
- 变化：文件更新后做块级 diff（新增 / 修改 / 删除）；正文标记、目录标记、顶部计数；“只看变化”；删除块 ghost。

**验收**

- 3 条批注从选中到发送不超过 2 分钟，无复制粘贴。
- 刷新或重开，草稿还在；发送后进入会话日志。
- 两个文档的附件同时发送，各自清空并各落一份旧版快照；只发一个时另一个不受影响。
- Web Clipper 的附件与手动移除附件都不会误触发清空。
- Agent 改完，页面显示“本轮 N 处变化”，只看变化能完成确认。
- 删除的内容可见；无法定位的批注有明确提示，不静默错位。

**不做**：编辑、富渲染、Agent 工具、审批状态机、标签、译文批注。

## 6. P3 编辑（M）

**目标**：让用户不离开页面就能做小修，并且不与 Agent、批注打架。

**交付**

- 模式切换：阅读 / 编辑；编辑态明显，有保存、取消、脏标记、离开确认。
- 源码编辑：等宽、语法高亮（可后置）、行号（可选）、Cmd/Ctrl+S。
- 保存：`ctx.fs` 版本守卫；原子写；成功后重渲染。
- 冲突：版本不一致时给“重新加载（保留草稿可复制）/ 以我的版本覆盖（二次确认）/ 取消”。
- 并发提示：Agent 运行中进入编辑先提示并二次确认；保存时仍以版本为准。
- 互斥：未发送批注禁止进入编辑；译文或对照进入编辑先切回原文；保存后译文失效、批注重锚、diff 标“你的修改”。
- 范围：仅普通 UTF-8 `.md`；大小上限；拒绝符号链接。

**验收**

- 改一段、保存、渲染立即更新；标题变化时 tab 标题同步。
- Agent 同时改同一文件，保存失败进冲突态，三选一可用，不丢草稿。
- 未发送批注时不能进编辑；保存后批注不静默错位。
- 编辑与阅读切换不丢阅读位置（同一次会话内）。

**不做**：WYSIWYG、块级编辑、自动保存、多文件编辑。

## 7. P4 富渲染与阅读打磨（M）

**目标**：把“读得舒服”补齐，形成完整的第一印象。

**交付**

- 目录：H1–H4、滚动高亮、折叠、当前章节、窄栏收起。
- Callout：`> [!type]` 常见类型与语义色。
- Mermaid：懒加载；错误回退源码并可复制错误；全屏查看。
- 数学：行内与行间；懒加载。
- 代码块：复制、换行、语言标签；表格横向滚动；图片放大。
- 排版：正文宽度、字阶、行高、中文标点；front matter 元信息卡。
- 富组件上的组件级批注入口补齐。

**验收**

- 图能出、失败可退；明暗、窄栏、全屏一致；200 段文档仍小于 1 秒。
- Mermaid chunk 不进入首屏；首次渲染不阻塞正文。

**不做**：Markmap、Gherkin、思维导图、导出 PDF、主题系统。

## 8. P5 Agent 闭环（M）

**目标**：让 Agent 主动发起审阅，并把批注作为结构化结果拿回去。

**交付**

- 工具：名称待定（用到时再讨论）打开当前会话的文档审阅；默认非阻塞，返回“已打开”。
- 审批：通过 / 需修改动作，生成结构化结果；可作为用户消息或工具结果。
- Skill：长文档写作与审阅流程（写文件、标题稳定、按批注迭代、不要整篇重写）。
- 提示词（可选）：长文写文件而不是贴聊天。
- 阻塞模式（可选）：等待批注并返回结构化数组，带超时与取消。

**验收**

- Agent 写完文档调用工具，用户批注后 Agent 能拿到结构化结果继续改。
- 不复制粘贴；工具失败或无 UI 时优雅降级。
- 通过 / 需修改在会话里可追溯。

**不做**：多人审批流、审阅任务队列、自动改写。

## 9. P6 收口（M）

- 与 `friendly-expression` 的边界落地；确认旧翻译插件已无场景需要承接。
- 设置页、locale、图标、README、卸载清理、数据保留说明。
- 大文档性能、可访问性、键盘操作、错误态。
- 真实会话端到端验收；发布检查。

## 10. 横向风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 接管默认渲染的兼容成本 | 用户失去原生分页、行跳转 | 超限回退原生；保留下拉；滚动记忆由父级容器保留 |
| 正文渲染崩溃 | 预览白屏 | 自带错误边界 + 切换原生指引 |
| Mermaid 体积 | 首屏变慢 | 懒加载 chunk，按需加载 |
| 大文档性能 | 目录、diff、编辑卡顿 | 块级渲染、按需虚拟化、大小上限 |
| 并发写冲突 | 覆盖丢失 | 版本守卫 + 冲突态，永不静默 |
| 批注锚点跨修订 | 错位 | 行级偏移 + 前后文 + 显式失效，不静默降级 |
| 存储膨胀 | 基线快照占空间 | 每文档保留 K 轮、大小上限、清理说明 |
| Agent 不知道有审阅面 | 用不起来 | P5 skill 与工具，README 引导 |
