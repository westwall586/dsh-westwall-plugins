## 1. 阅读宽度：散文限宽、组件铺满、图单独限宽（方案 C）

**现象**：右侧栏拉宽后，正文两侧留下大块空白。`client/src/styles.css:75-79` 对
`.am-heading / .am-paragraph / .am-list / .am-quote / .am-callout / .am-divider`
设了 `max-width: 44em; margin-inline: auto`；44em 按内容字号算，默认 14px 时约
616px，而宽侧栏常见 700–1100px。

**确认的做法**（2026-11-25 讨论）：

| 类别 | 现在 | 改后 |
|---|---|---|
| 散文：标题、段落、列表、引用、callout 正文 | 44em | 约 66em；窄栏用容器查询退回 44em |
| 表格、callout、代码块 | 不限宽（铺满） | 不变 |
| Mermaid / Markmap | 不限宽（`width: 100%`） | **加最大宽度**，避免节点被拉散、只能靠全屏看清 |
| front matter 卡 | 44em | 跟着散文一起改，否则宽栏里比正文窄一截 |

**实现要点**

- 插件根 `[data-active-markdown]` 已有 `container-type: inline-size`
  （`client/src/styles.css:4`），窄栏自适应直接写 `@container`，不要加 JS 测量。
- 图的限宽值与散文的 66em 分开定：图没有“行宽”概念，取 `96em` 一类的容器上限。
- 侧栏滚动条是 overlay（`--dsh-scrollbar-width: 5px`），`margin-inline: auto`
  居中的内容会相对视觉中心偏左约 2.5px；不值得为它改布局，记录在此避免以后重复调查。

**验收**：侧栏从最窄拖到最宽，散文行宽在 44em–66em 之间变化而不突兀；表格、代码块、
callout 铺满栏宽；Mermaid 图在宽栏里不铺满整屏、在窄栏里仍能透过全屏看清。

## 2. 源码视图字号绑定 `--dsh-content-font-size`

**现状**：`client/src/edit/editor.tsx:41-46` 已绑 `var(--dsh-code-font-size)`（默认
11px，用户可配 10–16px）。11px 读 Markdown 源码偏小，且与旁边渲染视图（14px）差一档。

**确认的做法**（2026-11-25 讨论）：改为 `var(--dsh-content-font-size)`，跟随宿主的
“内容字号”设置，与主题插件对正文的调整保持一致。

**代价与配套**

- 源码编辑器字号将不再与代码块一致（代码块走 `--dsh-code-font-size`）。这是有意的取舍：
  编辑器是“被阅读的内容”，不是“被引用的代码”。
- `.cm-scroller` 的 `lineHeight: 1.65` 是按 11px 调的，换成 14px 后行距偏松；同一次改动里
  调到与主题 markdown 行高一致（或 1.5–1.6 之间）。
- 若用户的主题插件只改字体族与颜色、没有设置宿主的内容字号 token，这里仍是默认 14px。
  这不是插件的 bug，验证时以宿主外观设置里的“内容字号”滑杆为准。

**验收**：在宿主外观设置里把内容字号从 10px 拖到 22px，源码视图字号跟着变，行高不崩，
保存/冲突/外部变更等编辑流程回归通过。

## 3. 批注归档（独立功能）

**定位**：用户做过的每一条批注都留在一个单独的归档区，不管 Agent 有没有对应处理，
用户都能核查这份文档的演进路径。它**独立于易失 store**（
[STATE-STORE-TECH.md](STATE-STORE-TECH.md)），有自己的持久化。

**本轮不做**。在它落地前，清批注就是清：文档关闭或外部修改时，批注内存与磁盘
记录一并清除。归档功能完成后，这两处“清”改为“清入归档”。

**要定的事**：归档的存放位置与格式；归档与“这一轮反馈已发送”的关系；归档区的
入口（插件页？文档侧栏？对话里？）；是否跨会话可查。

## 4. 关闭 dirty 页签的二次确认

当前定案是“关闭即放弃”：主动关闭页签时翻译终止、批注/翻译/编辑草稿/视图全清，
不做确认弹窗。后续在 UI 层补一次确认（仅当编辑草稿 dirty 或存在未发送批注时），
避免用户误关导致内容丢失。
