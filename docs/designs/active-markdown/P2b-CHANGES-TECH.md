# Active Markdown P2b 技术方案：块级更新标记

> 状态：设计定稿（2026-11-18，评审 2），已实现（2026-11-18）；Web 版实机复核通过，桌面版待复核。定位见 [POSITIONING.md](POSITIONING.md)，阶段见 [ROADMAP.md](ROADMAP.md)，批注与旧版快照见 [P2-ANNOTATION-TECH.md](P2-ANNOTATION-TECH.md)。
>
> 本文只覆盖 P2b：把「上次发送反馈时的全文快照」当作基线，在文件被改过后标出需要读的地方。批注、附件、发送判定、旧版快照已在 P2a 完成，本文不改它们的行为，只加一个只读的基线读取接口、一层块级 diff，以及一个最小目录。
>
> 评审后的收敛：不做新增 / 修改 / 删除的分解，不做删除 ghost，不做「只看变化」模式。只标记本次批注提交后仍存在且被更新的段落与组件，并在目录里标出被更新的章节。最小目录（H1–H6、跳转、章节更新点）并入本轮；滚动高亮、折叠、当前章节、常驻侧栏留到 P2c。

## 1. 目标与非目标

**目标**

- 打开或刷新一份有已发送审阅轮次的文档时，如果文件在该轮之后被改过，页面能把阅读注意力引到更新处：
  - 顶部只给一句「上次反馈后更新了 N 处」，不分解新增 / 修改 / 删除。
  - 正文按块标记被更新的段落、标题、组件；新增与修改不区分。
  - 目录列出 H1–H6，被更新的章节带标记，点击可跳转；工具栏的目录按钮在有章节更新时带一个小点。
- 变化只作为阅读辅助，不影响批注、选区、锚点、翻译与文件本身。
- 没有可比较的基线、没有更新、或正在一轮未发送的批注里时，顶部提示与标记完全不出现。

**非目标**

- 新增 / 修改 / 删除的分类、分类颜色、分类计数。
- 删除内容展示与删除 ghost。删除只参与 diff 对齐，不进入界面。
- 「只看变化」模式；不隐藏未变内容，不做过滤视图。
- 词级、字符级、表格单元格级 diff；按字标红。
- 接受 / 拒绝单处变化、合并、反向应用。
- 译文视图里的变化标记。译文是视图，原文才是真源；源文件变化时译文本身会标过期。
- front matter 的变化计数。front matter 不在块树里，本轮不伪造块。
- 目录的滚动高亮、折叠、当前章节跟踪、常驻侧栏与窄栏收起（P2c）。
- 关闭状态的持久化。关闭只影响当前这次打开的顶部提示。

## 2. 本轮定下的结论

| 项 | 结论 |
|---|---|
| 基线 | 最近一次**已发送**且有全文快照的轮次；最新一轮快照缺失就不显示，不向更早的轮次回退 |
| 未发送轮次 | 有 pending 时不显示更新，避免和「附件已过期 / 正在审阅」打架 |
| 判定口径 | 渲染语义：忽略换行、列表符号、围栏风格；文字、链接地址、图片、强调变化算更新 |
| 粒度 | 只到顶层块；列表、引用内部变化算整块更新 |
| 状态 | 统一为 `updated`；新增与修改不区分 |
| 删除 | 不计数、不标记、不展示；只参与对齐 |
| 计数 | 顶部只给「N 处更新」，无新增 / 修改 / 删除分解 |
| 呈现 | 顶部一句 + 正文块标记 + 目录章节更新点 |
| 目录 | 最小 H1–H6 目录与章节更新点在本轮；滚动高亮、折叠、当前章节、侧栏形态留到 P2c |
| 只看变化 | 不做 |
| 触发 | 文档就绪、`revision` 变化、未发送轮次消失时各取一次基线，不轮询 |
| 关闭 | 顶部提示本次打开内可关闭；正文标记与目录点不受影响；刷新后提示重新出现 |
| 存储 | 不新增表、不新增工作区文件；只加一个只读 Host 方法 |

## 3. 基线

### 3.1 什么是基线

P2a 在「加入输入框」时把 `state.text` 写成 `reviews/pending/<roundId>.md`，发送成功后 `rename` 到 `reviews/<镜像路径>/<roundId>.md`，并在旁边写 `<roundId>.json`。

- 基线就是这份 `<roundId>.md` 的全文。
- 只认**已发送**的轮次；pending 只是「准备中」，不是用户已经确认过的基线。
- 基线按「最近一轮」取，不提供轮次选择器。旧轮次仍按 P2a 的 5 轮 / 30 天 / 50 MiB 规则清理。

### 3.2 为什么最新一轮快照缺失时不回退

如果第 N 轮写入失败（`snapshotMissing`），但第 N-1 轮还有快照，用第 N-1 轮做 `diff` 会把「N-1 之后、N 之前」的改动重新算进来。那部分用户已经看过、也已经批注过了，再显示成「上次反馈后」会误导。

所以：**最新一轮不可比较，就整轮不显示**。发送时已经提示过「旧版未保留」，这里不重复报错。

### 3.3 选择规则

1. 用 `documentMirror(workspace, path)` 找到该文档的轮次目录。
2. 只读该目录下成对的 `<roundId>.json` + `<roundId>.md`；缺任一个都不算。
3. `meta.sourcePath` 必须与 `documentMirror(workspace, path).sourcePath` 相同（工作区内是相对路径，工作区外是绝对路径），防止镜像目录命名碰撞或文件改名后读到别人的轮次。
4. 按 `meta.createdAt` 降序，时间相同再按文件 mtime 降序。
5. 取第一条；它带 `snapshotMissing` 或 `.md` 读不到时返回 `null`，不继续找。
6. pending 目录不参与。

## 4. `Host` 接口

### 4.1 契约

```ts
interface ReviewLatestRequest {
  sessionId: string
  path: string        // 规范绝对路径，与批注草稿一致
}

interface ReviewLatestView {
  roundId: string
  createdAt: string
  text: string        // 该轮发送前的全文
}
```

- `reviewLatest` 返回 `null` 表示「没有可比较的基线」：没有轮次、最新一轮快照缺失、元数据损坏、路径不匹配。这些都不算错误。
- 真正的 I/O 失败（读权限、磁盘错误）抛 `read-failed`；未知会话、非法路径沿用现有错误码。
- 只读，不触发清理；清理仍在 `prepare` / `commit` 时做。
- 不返回 `annotations` 与 `feedback`。P2b 不需要，返回只会扩大契约。

### 4.2 实现位置

- `src/annotate/reviews.ts`：`ReviewStore.latest(input)`；复用 `rootsOf`、`documentMirror`、`roundDirectory`、`reviewRoundSchema`。
- `src/index.ts`：`reviewLatest(sessionId, path)`，走 `callAnnotation`，并把方法加进 `METHODS`。
- `client/src/context.ts`：`HostBridge.reviewLatest` 与请求 / 返回类型。
- `client/src/host.ts`：`WIRE.reviewLatest = ['sessionId', 'path']` 与对应 descriptor。
- 不加存储表，不改 `cordis.patch.yml`。

### 4.3 读 `.md`，不读 `meta.sentText`

`ReviewRound.sentText` 是发送时输入框里的文本，可能为空，不是文档全文。基线只能来自 pending 转正的那份 `.md`。这一点在实现时容易读错字段。

## 5. 块级 diff

### 5.1 块内容键

diff 不直接比源码行，也不只比纯文本，而是给每个块算一个**渲染语义键**：

- 文本：`\s+` 折叠为单个空格并去首尾；软换行与硬换行都按一个空格处理。
- 行内结构保留：`strong` / `em` / `del` / `code` / `link` / `image` 的层级、`href`、`src`、`alt` 都进键。
- 标题：层级 + 行内键。
- 代码：语言 + 内容；只归一化行尾空白，保留缩进。
- 表格：表头、每行、每个单元格的行内键；`align` 也进键（对齐是可见变化）。
- 列表：`ordered` / `start` / 每个 item 的 `task`、文本、子块键。
- 引用：子块键递归。
- 分隔线：固定键。

这样做的好处：

- 只把段落重新折行、把 `-` 换成 `*`、把围栏从 ``` 换成 ~~~，不算更新。
- 改链接地址、换图片、加粗改斜体、改表格对齐，算更新。
- 代码块内空白敏感，缩进变化算更新。

不使用源码逐字比较，是因为 Agent 经常会统一列表符号或重排段落，逐字比较会把整篇标成改动；不使用纯文本投影，是因为链接地址与图片替换会漏掉。

### 5.2 匹配

输入是新旧两棵块树的**顶层** `Block[]`。步骤：

1. 先削掉首尾完全相同的块（键相等），缩小中间段。
2. 中间段用 Myers 求匹配；设距离上限 `MAX_D`（初值 1200）。超过上限时停止 Myers，中间段直接当作「全部更新」，不再尝试匹配。
3. Myers 匹配上的块不标；没匹配上的新块默认都是 `updated`。
4. **移动消解**：没匹配上的新块，如果它的键出现在没匹配上的旧块里，视为移动，不标更新、不计数；每个旧键只消解一次。
5. 没匹配上的旧块（删除）直接丢弃，不计数、不展示；它只影响后续块的下标。

为什么不需要区分新增与修改：两者对读者都是「这一处要重新看」。所以只需要回答「这个新块在旧文档里有没有同键对应」；没有就是 `updated`。替换（旧段换成新表）自然只算新表 1 处，旧段不进入计数。

退化路径：超过 `MAX_D` 时，中间段的新块全部标 `updated`，不做移动消解。极端整篇重写会显得很吵，但不会卡死。

### 5.3 输出

```ts
interface DocumentDiff {
  /** 与顶层块下标一一对应；undefined 表示未更新。 */
  statuses: readonly ('updated' | undefined)[]
  counts: { updated: number }
}

function diffBlocks(before: readonly Block[], after: readonly Block[]): DocumentDiff
```

- `counts.updated` 等于 `statuses` 中 `updated` 的数量。
- 不返回删除块列表，不返回分类计数。
- 纯新增：1 处更新。
- 替换：旧段换成新表，新表 1 处更新，旧段不计数。
- 纯删除：0 处更新。
- 纯移动：0 处更新（退化路径除外）。

### 5.4 章节更新点

```ts
function updatedSections(blocks: readonly Block[], statuses: readonly ('updated' | undefined)[]): readonly string[]
```

返回被更新块所在章节的标题锚点，供目录打点：

- 维护一个 H1–H6 的标题栈；遇到标题时按层级压栈 / 截断。
- 更新的块是标题时，标它自己的 `anchor`。
- 更新的块是正文 / 列表 / 引用 / 表格 / 代码时，标当前栈顶标题。
- 不标父章节：H2 里的段落更新，只标 H2，不标 H1。折叠与父章节汇总留到 P2c。
- 第一个标题之前的内容没有目录条目，不产生章节点；正文标记与计数仍然生效。
- 删除不产生章节点。一个章节如果只被删了内容、没有新增或修改，目录不打点，这与「删除不展示」一致。

### 5.5 目录条目

```ts
interface TocEntry {
  anchor: string
  text: string
  level: number      // 1..6
}

function tocEntries(blocks: readonly Block[]): readonly TocEntry[]
```

按文档顺序取 H1–H6 标题，与 Markdown 的六级标题完全对齐。没有标题时不显示目录入口。

## 6. 渲染与交互

### 6.1 顶部提示

在 `.am-toolbar` 下方、正文上方，复用 `.am-notice` 的视觉语言：

```text
上次反馈后更新了 4 处                                    [关闭]
```

- 只在 `view === 'source'` 且 `counts.updated > 0` 时出现。
- 不出现新增 / 修改 / 删除分解，不出现「只看变化」按钮。
- `role="note"`；关闭按钮用现有 `.am-toolbar-action` 尺寸。
- 关闭只隐藏这句提示；正文标记、目录按钮上的点、目录里的章节点都保留。
- 文件文本再次变化或出现新轮次后，提示重新出现。
- 文案走 `client/src/locales.ts` 的 `diff.*`，中英各一份。

### 6.2 正文标记

- `MarkdownView` 接受可选的 `diff`；`renderBlock` 把状态写到块根元素的 `data-diff="updated"`。
- 表格、代码块通过 `ComponentFrame` 的 `data-diff` 暴露，状态只来自其顶层块。
- 只有一种状态、一种样式：块首一根 3px 竖条，颜色取 `--dsw-alias-link`。不加背景色、不加左边框，更新过的段落不会被读成引用。
- 文本块（标题、段落、列表、引用、分隔线）的竖条画在页边（`left: -14px`），不占排版空间，开关不引起跳动。
- 组件（表格、代码、Mermaid、导图、公式、Callout）自带 `overflow: hidden`，页边竖条会被裁掉，所以竖条画在组件头部（`.am-component-head`）的左缘、与标题行垂直居中；Callout 的头部缩进在卡片内 14px，竖条落在语义色边内侧 5px 处。
- 工具栏「更新 N 处」跳转时给目标块加 `am-diff-flash` 类；组件把同一动画挂到头部竖条上，跳动在左缘可见。

### 6.3 目录与章节更新点

- 工具栏加一个「目录」切换按钮；文档没有 H1–H6 标题时不显示。
- 有章节更新时，按钮带一个小圆点；圆点不是计数，只表示「目录里有更新章节」。
- 点开后，在工具栏下方展开一个可滚动的目录块，不挤压正文宽度：
  - 列出 H1–H6，按层级缩进；
  - 被更新章节的条目在右端带圆点，与标题文本分开、形成右侧一列，不用标题缩进换位置；圆点用 `title` / 无障碍文案说明「已更新」；
  - 点击条目滚动到对应标题（用标题元素已有的 `data-anchor`），滚动后收起目录；工具栏是 sticky 的，再点一次即可重开；
  - 标题样式补 `scroll-margin-top`，避免跳转后被 sticky 工具栏挡住。
- 目录只列标题，不做当前章节高亮、不做滚动联动、不做折叠；这些是 P2c 的打磨项。
- 目录只在原文视图显示。译文视图不显示目录入口、更新提示与正文标记。
- 目录是导航，不是 diff 专属：没有更新时也可以打开，只是没有圆点。

### 6.4 删除不展示

- 删除块不生成 ghost、不占位、不计数。
- 一个章节如果只删了内容，正文与目录都不标记；顶部提示也不出现。
- 这是有意取舍：本轮只把读者引向「现在还能读、且需要读」的内容，不做版本回放。

## 7. 状态与触发

本轮的运行时状态都挂在文档 Body 上，不跨文档共享：

```ts
const [latest, setLatest] = useState<ReviewLatestView | null>(null)
const [dismissed, setDismissed] = useState<{ roundId: string, text: string } | null>(null)
const [tocOpen, setTocOpen] = useState(false)
```

- `latest` 的取数 effect 依赖：`state.status`、`revision`、`draftKey`、`pendingReview?.roundId`、`host`。
- `draftKey` 为 `null`、`pendingReview` 非空、或 `state` 不是 `ready` 时清空 `latest` 并跳过请求。
- 请求带自增 token；文档切换或依赖变化后旧响应直接丢弃。
- 取到后先比较 `normalize(latest.text)` 与 `normalize(state.text)`；相等就当没有更新，不解析、不 diff。
- 解析基线用 `useMemo`，只随 `latest.text` 变化；diff 用 `useMemo`，只随两份解析结果变化；章节点用 `useMemo`，只随块与状态变化。
- 有 pending 时隐藏更新；发送成功、pending 清空后 effect 重新取数，新轮次成为基线，diff 归零。
- 手动移除附件（pending 被 detach）也会重新取数，回到上一轮已发送基线。
- `documentKey` 变化时清空 `latest`、`dismissed`，并关闭目录。
- 请求失败静默：没有基线就当没有更新，不在正文里报错。
- diff 变空时退出顶部提示与目录点；目录本身仍可打开。

## 8. 边界与失败

| 情况 | 行为 |
|---|---|
| 最新一轮 `snapshotMissing` / `.md` 缺失 | 不显示更新，不回退旧轮次 |
| 元数据 JSON 损坏或 schema 不符 | 跳过该轮；最新一轮不可用时不显示 |
| 当前文本与基线相同 | 不显示；没有标记与目录点 |
| 改动后又改回基线 | 同上，不显示 |
| 只有 front matter 变化 | 不显示（front matter 不是块；本轮已知取舍） |
| 只改换行、列表符号、围栏风格 | 不算更新（渲染语义键归一化） |
| 只删除、没有新增或修改 | 0 处更新；不显示提示、不标章节 |
| 同一块只换位置 | 不标更新（键相同的移动消解） |
| 整篇重写 | 计数很大，所有章节打点；不卡死，但会显得很吵 |
| 没有 H1–H6 标题 | 不显示目录入口；正文标记与顶部提示照常 |
| 更新发生在第一个标题之前 | 正文标记与计数照常；目录没有对应条目 |
| 只更新 H5 / H6 | 正文标记该标题；目录标该标题本身 |
| 跨工作区打开同一绝对路径 | 不命中另一个工作区的基线（与附件归属一致） |
| pending 未发送 | 不显示更新；P2a 的附件过期提示继续负责 |
| 发送失败、pending 仍在 | 不显示更新 |
| 译文视图 | 不显示目录、提示与标记 |
| 同一文档两个 tab | 各自取数、各自关闭，互不同步；基线相同 |

文本统一按 `\r\n → \n`、去末尾换行后比较；重复读取不会因为换行风格产生假 diff。

## 9. 性能

- 基线全文最多 2 MiB（与 `READ_CAP` 一致），解析一次，按文本 memo。
- 只有归一化文本不同才解析与 diff；相同就提前返回。
- Myers 有 `MAX_D` 上限；退化路径是线性的。2000 个顶层块、少量改动时目标 < 50 ms。
- 章节点与目录条目都是线性扫描，只随块树变化重算。
- 不轮询、不 watch：只依赖预览的 `revision`、文档切换与 pending 状态。

**Diff（`test/diff.test.ts`）**

- 完全相同 → `updated = 0`。
- 改一段 / 加一段 → 各 1 处 `updated`，下标正确。
- 纯删除 → 0 处 `updated`，没有状态。
- 替换（段落换成表格）→ 新表 1 处 `updated`，旧段不影响计数。
- 同一块换位置 → 0 处 `updated`；移动且改写 → 1 处。
- 列表项内容变化、引用子块变化 → 顶层整块 `updated`。
- 链接地址、图片 src、强调变化 → `updated`；仅折行、列表符号、围栏风格变化 → 不变。
- 代码缩进、表格单元格、对齐变化 → `updated`。
- 全文重写走退化路径：中间段新块全部 `updated`，计数稳定。
- 空旧文档 / 空新文档。

**章节与目录（同文件）**

- H2 下的段落更新 → 只标 H2；H1 不标。
- H2 标题本身更新 → 标 H2。
- H5 标题更新 → 标 H5。
- 第一个标题之前的块更新 → 没有章节点。
- 只删除的章节 → 没有章节点。
- `tocEntries` 只含 H1–H6，顺序与层级正确。

**实机**

1. 在测试文档里写批注并发送，确认 `reviews/<文档>/<roundId>.{md,json}` 存在。
2. 用脚本模拟 Agent：改一段、加一段、删一段、改一个标题、改一个链接地址、移动一段。
3. 刷新页面：顶部只显示「上次反馈后更新了 N 处」；正文被更新的块有左侧标记；新增与修改样式一致。
4. 打开目录：被更新章节带圆点；点击条目能跳到对应标题；工具栏按钮有圆点。
5. 关闭顶部提示：标记与目录点仍在；刷新后提示重新出现。
6. 只删一段再刷新：没有提示、没有章节点、没有 ghost。
7. 把文件改回基线：提示、标记、目录点全部消失；目录仍可打开。
8. 再发一轮批注：基线切换，提示归零；Agent 再改后按新基线显示。
9. 译文视图不出现目录、提示与标记；批注、选区、锚点行为不变。
