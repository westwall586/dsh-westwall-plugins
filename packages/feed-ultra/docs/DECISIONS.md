# 设计决定

记录已经定下来的取舍。每条写清楚选了什么、为什么、代价是什么。

## 产品范围

**决定**：订阅任何资讯源，RSS 只是其中一种。资讯收进 DSH 桌面端，按天阅读，AI 负责翻译和解读。

**原因**：只做 RSS 阅读器会撞上一批成熟产品。DSH 里的价值在于资讯能进工作区，能被 Agent 直接读和加工。

**代价**：每接一类来源都要写适配器和能力声明，比只做 RSS 宽。AI 解读做得越深，模型成本和响应时间越需要控制。

## 抓取成本

**决定**：把 ego-lite 的取数脚本固定在插件里，抓取复用本机登录态。ego-lite 需要用户自己安装，官网是 https://lite.ego.app/。

**原因**：大多数资讯站不提供 API，第三方抓取服务按次计费。浏览器会话是用户已经付过费的部分。

**代价**：需要本机安装 ego-lite 并登录目标站点。脚本依赖页面结构，站点改版会让脚本 drift。单次抓取约 10 秒，不适合高频轮询。

## 数据放在工作区

**决定**：所有数据落在 `<工作区>/.dsh-feeds/`，插件不建数据库，也不上传。

**原因**：工作区是 DSH 里 Agent 和用户共享的地方，普通 JSON 可以直接读。换工作区就换一套订阅，迁移和备份都是文件操作。

**代价**：并发写要靠插件自己串行化。跨机器同步需要用户自己解决。

## 按天分区与每日一次

**决定**：一份内容按天保存，每天自动抓一次，已读状态跨天合并。

**原因**：资讯是快照，不是可变记录。按天分区让保留窗口、历史回看和补拉都有明确边界。

**代价**：当天多次抓取要按 `naturalKey` 合并，不能简单覆盖。跨天去重依赖哈希和自然键。

## 源能力集中在 registry

**决定**：source id、适配器、节奏和能力只在一个注册表里声明。

**原因**：能力差异如果散在引擎和界面里，加一个来源要改很多分支。集中之后，界面按能力决定显示什么。

**代价**：能力字段要一次设计对，后续加字段要改所有适配器。

## 翻译按渠道开关

**决定**：翻译是渠道能力，不是全局开关。模型可以跟随 DSH 默认，也可以显式指定。

**原因**：不同来源的文本价值不同，有的渠道不需要翻译。跟随默认让用户不用重复配置。

**代价**：每个渠道多一组设置。模型不可用时只能报错和重试，不能静默换模型。

## 没有后台进程

**决定**：调度只在 DSH 运行时工作，关闭期间不抓取，也不补历史天。

**原因**：插件是 DSH 的一部分，装一个常驻进程会让卸载和排障都变复杂。

**代价**：错过的时间窗不会自动补。用户打开面板时才能看到补抓结果。

## 数据目录不迁移

**决定**：目录名固定为 `.dsh-feeds`，插件不探测旧目录，也不改名。

**原因**：插件还没发布，为一次改名写迁移逻辑没有长期价值。目录名是契约，写进文档就够。

**代价**：从旧版本升级的用户要自己改一次目录名。

## TS 直载加 esbuild

**决定**：宿主半体保持 TS 直载，`exports` 指向 `src/index.ts`。浏览器半体用 esbuild 打成 `client.js` 并入库。

**原因**：旧插件就是这个形态，迁入仓库时不改运行时能减少风险。esbuild 只处理浏览器侧，配置简单。

**代价**：宿主代码只能用可擦除的 TS 语法。`client.js` 是产物，改客户端源码后必须重新构建并提交。

## 客户端 bundle 用带 scope 的包名

**决定**：`__ModuleLoader__.load` 的 id 写成 `@westwall/dsh-feed-ultra`。`CLIENT_CONTRIBUTION.package` 和 RPC 前缀保持不带 scope 的 `dsh-feed-ultra`。

**原因**：DSH 的 client-modules 按包名识别 bundle。注册 id 和包名不一致时，宿主报 `loaded without registering`，整个插件被跳过。旧插件没有 scope，所以这个差异没暴露过。

**代价**：两个名字看起来不一致，改动时容易只改一处。构建脚本和 `client/src/api.mjs` 必须分开维护。

## 命名

**决定**：包 `@westwall/dsh-feed-ultra`，插件 id `dsh-feed-ultra`，目录 `packages/feed-ultra`。显示名英文 `Feed Ultra`，中文「资讯工作台」。

**原因**：英文短，能当品牌念。中文直说功能，适合侧栏入口。三处技术身份保持一致。

**代价**：显示名和技术名不是同一个词，描述里要把两者连起来。

## 方向

接下来做两件事。

第一件是把「任何」做实：更多来源类型，以及不用每次写适配器就能接一个网页。

第二件是把 AI 解读做深：跨来源摘要、按主题聚合、把结论写回工作区。

这两件事都不改变上面的数据契约。
